  State Management

  auth-store.ts — Persisted to localStorage (auth-storage):
  - Tracks: user, isAuthenticated, showAuthModal, authStep, authFlow, userAuthStep, providerAuthStep
  - Controls the entire multi-step auth/onboarding modal flow
  - Actions: startUserFlow, startProviderFlow, nextUserStep, nextProviderStep, signOut, etc.

  categories-store.ts — In-memory with 5-minute TTL cache:
  - Auto-fetches on first access via useCategories() hook
  - Computed getters: featuredCategories(), topLevelCategories()

  ---
  Key Data Flows

  Login:

  ▎ SignInForm → POST /auth/login → store tokens → GET /onboarding/status → route to onboarding or dashboard

  User Registration:

  ▎ SignUpForm → POST /auth/register → email OTP → 8-step onboarding (interests, location, profile, experience, docs) → POST /onboarding/complete

  Provider Registration:

  ▎ Same signup → 9-step provider onboarding (bio, skills, coverage, documents) → pending review state

  Service Creation:

  ▎ /dashboard/services/new → collect title/category/plans/addons/images → POST /services (FormData) → redirect to services list

  Bot Chat:

  ▎ BotChatBox generates conversationId on mount → user sends message → POST /support/bot → displays markdown response → no auth required

  Admin:

  ▎ Dashboard with Recharts revenue graphs → manage users (PATCH /users/{id}/status), categories (full CRUD), disputes, services across all providers

## Architecture

### Module Structure

Each feature domain is a self-contained NestJS module under `src/`. Key modules:

- **auth** — JWT authentication, OAuth (Google/Apple/Facebook/Twitter), token refresh
- **users** — User profiles, verification, subscriptions
- **services** — Provider service listings, plans, addons
- **orders** — Order lifecycle management
- **chat** — Real-time user-to-provider messaging (WebSocket via Socket.io)
- **botChat** — AI support chatbot using OpenAI (KWADWO assistant)
- **quote** — Custom quote request flow between clients and providers
- **dispute** — Conflict resolution with admin notes
- **analytics** — Metrics and reporting
- **onboarding** — New user onboarding flow
- **common** — Shared decorators, guards, filters, services, utils, seeders

### Global Setup (app.module.ts / main.ts)

- **API prefix**: `/api`
- **Global JWT guard** applied to all routes — use `@Public()` decorator to skip auth
- **Global exception filter** — standardized error responses
- **Validation pipe** with `transform: true` and `whitelist: true` enabled globally
- **Winston logging** to console and files
- **Seeder** auto-runs on startup (admin user + categories)
- Static files served from `/uploads`

### Authentication Flow

JWT-based with access + refresh tokens. Passport.js + passport-jwt. Key decorators in `src/common/decorators/`:
- `@Public()` — marks endpoint as unauthenticated
- `@Roles(Role.ADMIN)` — role-based access control
- `@CurrentUser()` — extracts user from JWT payload

### Database

PostgreSQL via Prisma ORM. Schema at `prisma/schema.prisma`. Generated client outputs to `prisma/generated/`.

After any schema change: run `npm run prisma:generate` then `npm run prisma:migrate`.

### BotChat Module

AI support chatbot (`src/botChat/`):
- **Endpoint**: `POST /api/support/bot` (public, no auth)
- **LLM**: OpenAI GPT-4o-mini via `src/botChat/llm/client.ts`
- **State**: In-memory conversation tracking via `botChat.repository.ts` (Map of conversationId → responseId)
- **Prompts**: `src/botChat/prompt/chatbot.txt` (system prompt) + `Pavodah.md` (platform knowledge base)
- Requires `OPEN_AI_KEY` environment variable

### Common Services

Located in `src/common/services/`:
- **EmailService** — AWS SES or Resend (controlled by `EMAIL_PROVIDER` env var)
- **FileUploadService** — AWS S3 or Supabase storage
- **SmsService** — AWS SNS

### Response Pattern

Use `ResponseUtil` from `src/common/utils/` for consistent response formatting across all controllers.

  ---                                                   
  1. Application Bootstrap                              
                                                        
  src/main.ts                                           
                                                        
  The entry point. It:
  - Creates a NestJS app with NestExpressApplication    
  - Sets global prefix /api (so all routes are /api/...)
  - Applies a global ValidationPipe with transform: true
   and whitelist: true — this means DTOs auto-cast types
   and unknown fields are stripped                      
  - Enables CORS (open to all origins — you'll want to  
  restrict this in prod)                                
  - Serves static files (uploads) at /uploads           
  - Runs the Seeder on startup (creates admin user +
  default categories)                                   
  - Listens on PORT env var (default 3000)              
                                                        
  src/app.module.ts                                     
                                                        
  The root module. Registers every feature module and   
  two global providers:                                 
  - JwtAuthGuard as APP_GUARD — applied automatically to
   every route. To skip it, use @Public()               
  - ApplicationExceptionFilter as APP_FILTER — catches  
  every thrown error and formats the response           
  consistently                                          
              
  Also sets up Winston logging (console + file), writing
   to /log/info/ and /log/error/.

  2. Database Schema (Prisma)

  A listing created by a SERVICE_PROVIDER.

  COMPLETED → REFUNDED (or DECLINED)                    
  - Stores pricing snapshot at time of order (plan

  One review per order. Linked to client, provider, and

  ---             
  3. Authentication (src/auth/)
                                                        
  Registration Flow
                                                        
  POST /api/auth/register
  Body: { email, password, role? }
                                                        
  1. AuthService.register() is called                   
  2. Checks if email already exists → throws conflict   
  3. Hashes password with bcryptjs (salt = 12)          
  4. Creates User in DB (role defaults to USER unless   
  SERVICE_PROVIDER passed)                              
  5. Generates access token (JWT, ~15 min) + refresh    
  token (JWT, 30 days)                                  
  6. Calls sendEmailVerificationOtp() → generates
  6-digit OTP, stores in DB with 10-min expiry, sends   
  email           
  7. Returns { accessToken, refreshToken, user }        
                  
  ▎ The user gets tokens immediately on registration.   
  They can use the API before verifying email, but some 
  features may require emailVerified: true.             
                  
  ---
  Login Flow

  POST /api/auth/login
  Body: { email, password }                             
  
  1. Finds user by email                                
  2. Compares password with bcrypt.compare()
  3. Checks user.status === ACTIVE (suspended/deleted   
  users cannot login)                                   
  4. Updates lastLoginAt                                
  5. Generates new access + refresh token pair          
  6. Returns tokens + user
                                                        
  ---             
  Social Auth (Google)                                  
                  
  POST /api/auth/social
  Body: { provider: "GOOGLE", accessToken, idToken,
  role? }                                               
  
  1. Validates the Google idToken via Google's API      
  2. Extracts email, name, avatar from Google profile
  3. If user exists → update their Google data, generate
   tokens                                               
  4. If user doesn't exist → create new user (no        
  password, emailVerified: true since Google verified   
  it), generate tokens
  5. Returns tokens + user                              
                  
  ---
  Token Refresh

  POST /api/auth/refresh
  Body: { refreshToken }

  1. RefreshJwtStrategy validates the refresh token     
  signature
  2. Extracts userId from payload                       
  3. Generates new access + refresh token pair          
  4. Updates lastActiveAt
  5. Returns new tokens                                 
                  
  ---
  JWT Strategy & Guard
                                                        
  JwtStrategy (src/auth/strategies/jwt.strategy.ts):
  - Extracts Bearer token from Authorization header     
  - Verifies with JWT_SECRET                       
  - Calls authService.validateUser(userId) which:       
    - Loads user from DB                                
    - Checks status === ACTIVE
    - Attaches { id, email, firstName, lastName,        
  username, role, isActive, createdAt, updatedAt } to   
  req.currentUser                                       
                                                        
  JwtAuthGuard (src/auth/guards/jwt-auth.guard.ts):     
  - Registered globally in app.module.ts
  - On every request, checks for @Public() metadata → if
   present, skips auth                                  
  - Otherwise enforces JWT validation                   
                                     
  RolesGuard (src/auth/guards/roles.guard.ts):          
  - Reads @Roles() / @IsAdmin() / @IsServiceProvider()  
  metadata                                              
  - Compares req.currentUser.role against required roles
  - Throws 403 Forbidden if mismatch                    
                  
  ---                                                   
  Password Reset Flow
                                                        
  POST /api/auth/forgot-password → { email }
  POST /api/auth/verify-password-reset-otp → { email,   
  otpCode }
  POST /api/auth/reset-password → { email, otpCode,     
  newPassword }                                         
  
  1. forgotPassword() — always returns success (doesn't 
  reveal if email exists). Generates 6-digit OTP, stores
   with 15-min expiry, sends email                      
  2. verifyPasswordResetOtp() — validates OTP format,
  checks match, checks expiry, max 5 attempts           
  3. resetPassword() — re-validates OTP then updates
  password (bcrypt hash), clears OTP fields             
                  
  ---                                                   
  Phone Verification Flow

  POST /api/auth/send-phone-verification → {
  phoneNumber, countryCode }                            
  POST /api/auth/verify-phone → { phoneNumber, otpCode }
  POST /api/auth/resend-phone-verification              
                                                        
  Uses PhoneVerification table (separate from User). OTP
   sent via AWS SNS SMS.                                
  Phone numbers are formatted to E.164 (Ghana +233      
  handled specially).

  stateless JWT setup. The frontend discards the tokens.
   For true invalidation, you'd need a token blacklist
  (not currently implemented).

  File: is-public.decorator.ts                       
  Effect: Skips JwtAuthGuard                         
  ────────────────────────────────────────

  File: roles.decorator.ts                              
  Effect: Requires specific roles                    
  ────────────────────────────────────────              
  Decorator: @IsAdmin()                                 
  File: same                                         
  Effect: Shorthand for @Roles(Role.ADMIN)              
  ────────────────────────────────────────

  File: same                                            
  Effect: Shorthand for @Roles(Role.SERVICE_PROVIDER, 
    Role.ADMIN)                                         
  ────────────────────────────────────────           
  Decorator: @CurrentUser(field?)                       
  File: current-user.decorator.ts                       
  Effect: Injects req.currentUser (or a specific field)
    into the controller param                           
                  
  Usage example in a controller:
  @Get('me')   
  getMe(@CurrentUser() user: User) { ... }
                                                        
  @Get('id')                                            
  getId(@CurrentUser('userId') id: string) { ... }  //  
  'userId' maps to 'id'                                 
                                                        
  Global Exception Filter
                                                        
  src/common/filters/http-filter.filter.ts              
  
  Catches everything. Handles Prisma errors specially:  
  - P2002 (unique constraint) → 409 Conflict
  - P2003 (foreign key violation) → 400 Bad Request     
  - P2025 (record not found) → 404 Not Found       
                                                        
  Returns { message, data: null } in production. In dev,
   includes full error stack.

  14. How Roles Work End-to-End
                                                        
  USER (default)
                                                        
  - Can browse services (public)                        
  - Can create orders
  - Can start conversations                             
  - Can request quotes
  - Can raise disputes
  - Can complete onboarding                             
  - Cannot create services or access provider/admin
  endpoints                                             
                  
  SERVICE_PROVIDER                                      
                  
  - Set at registration with role: "SERVICE_PROVIDER" or
   promoted later
  - Can do everything USER can do, plus:                
  - Create/manage services, plans, addons, images
  - View & manage incoming orders                       
  - Respond to quotes, send offers                      
  - Access provider analytics                           
  - Upload verification documents                       
  - Must complete onboarding + have documents reviewed  
  to get isServiceProviderVerified: true                
                                                        
  ADMIN                                                 
                  
  - Set directly in DB or via seeder (auto-created on   
  startup from ADMIN_EMAIL/ADMIN_PASSWORD env vars)
  - Full access to all endpoints                        
  - Can manage user statuses, view all orders/disputes, 
  resolve disputes, review documents                    
  - Access admin analytics

  15. Frontend Integration Pattern
                                                        
  Headers
                                                        
  Every authenticated request must send:
  Authorization: Bearer <accessToken>

  Token Lifecycle                                       
  
  1. On login/register → store accessToken (15 min) and 
  refreshToken (30 days)
  2. When a request returns 401 → call POST             
  /api/auth/refresh with { refreshToken }               
  3. Store the new token pair, retry the original
  request                                               
  4. If refresh also fails → force logout (discard
  tokens, redirect to login)                            
                  
  Response Shape                                        
                  
  Every endpoint returns:                               
  { "message": "...", "data": { ... } }
  Errors return the same shape with data: null.         
                  
  File Uploads                                          
  
  Endpoints that accept files use multipart/form-data.  
  Send files as form fields alongside JSON data.
                                                        
  WebSocket (Chat)                                      
  
  Connect to the WebSocket server at the base URL.      
  Authenticate by passing the JWT token during the
  socket handshake. Listen for message events on the    
  conversation channel.

Testing the Support Chat System in Postman

  ---
  Prerequisites — Get a JWT Token

  First login as a User and save the token.

  POST http://localhost:3000/api/auth/login
  {
    "email": "user@example.com",
    "password": "yourpassword"
  }
  Save the accessToken from the response. Repeat this
  for an Admin account too (you'll need both tokens).

  ---
  Part 1 — REST API Tests

  Set header on every request:
  Authorization: Bearer <accessToken>

  ---
  1. Start a support conversation (as User)

  POST http://localhost:3000/api/support/conversations

  No body needed. Returns the conversation with a
  welcome bot message.

  Save the conversation.id — you'll need it for
  everything below.

  ---
  2. Get your conversations

  GET
  http://localhost:3000/api/support/conversations/my

  ---
  3. Send a message to the bot

  POST http://localhost:3000/api/support/conversations
  /:id/messages
  {
    "content": "Hello, I need help with my order"
  }
  Response will have both your message and the bot's
  reply.

  ---
  4. Send another message (bot continues responding)

  POST http://localhost:3000/api/support/conversations
  /:id/messages
  {
    "content": "Can I talk to a real person?"
  }

  ---
  5. Escalate to admin

  PATCH http://localhost:3000/api/support/conversation
  s/:id/escalate

  No body. Status changes to WAITING_FOR_ADMIN.

  ---
  6. View all conversations as Admin

  Switch to the Admin token.

  GET http://localhost:3000/api/support/admin/conversa
  tions

  Response is grouped:
  {
    "waiting": [...],
    "active":  [...],
    "closed":  [...]
  }
  Your conversation should appear in waiting.

  ---
  7. Admin joins the conversation

  PATCH http://localhost:3000/api/support/admin/conver
  sations/:id/join

  No body. Status changes to ACTIVE_WITH_ADMIN.

  ---
  8. Admin sends a message

  POST http://localhost:3000/api/support/conversations
  /:id/messages
  {
    "content": "Hi! I'm a support agent. How can I
  help you?"
  }
  Use the Admin token here.

  ---
  9. User replies back

  Switch back to User token.

  POST http://localhost:3000/api/support/conversations
  /:id/messages
  {
    "content": "Thanks! My issue is resolved."
  }

  ---
  10. Close the conversation

  PATCH http://localhost:3000/api/support/conversation
  s/:id/close

  ---
  Part 2 — WebSocket (Real-Time) Tests

  Postman supports Socket.io. Use New → Socket.IO
  request.

  ---
  Connect as User

  - URL: http://localhost:3000/support
  - Under Connection tab → add auth:

  Key: auth
  Value (JSON): {"token": "<user_accessToken>"}

  Click Connect.

  ---
  Connect as Admin (open a second Socket.IO tab)

  Same URL, use the admin token in auth. Admin
  auto-joins the support-admins room on connect.

  ---
  WebSocket events to test

  In the User tab — join the conversation room:

  Event name: support:join
  Message: "<conversationId>"

  ---
  Send a message:

  Event name: support:send_message
  Message:
  {
    "conversationId": "<conversationId>",
    "content": "Hello from WebSocket!"
  }

  Listen for support:message on both tabs — you should
   see the user message and the bot reply.

  ---
  Escalate to admin:

  Event name: support:escalate
  Message: "<conversationId>"

  → Admin tab should receive support:new_waiting event
   automatically (because admin is in the
  support-admins room).

  ---
  Admin joins (in Admin tab):

  Event name: support:join_as_admin
  Message: "<conversationId>"

  → User tab should receive support:admin_joined
  event.

  ---
  Admin sends a message (in Admin tab):

  Event name: support:send_message
  Message:
  {
    "conversationId": "<conversationId>",
    "content": "Hello from Admin!"
  }

  → User tab should receive support:message.

  ---
  Close conversation:

  Event name: support:close
  Message: "<conversationId>"

  → Both tabs receive support:closed.

  Quick Status Flow Reference

  Start conversation  →  status: BOT
  Send messages       →  bot replies automatically
  Escalate            →  status: WAITING_FOR_ADMIN
  Admin joins         →  status: ACTIVE_WITH_ADMIN
  Close               →  status: CLOSED
